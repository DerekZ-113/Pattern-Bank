# PatternBank V2.0 Release Plan

## Purpose

V2.0 is a major release. We do not merge partial V2.0 pillars directly into `main`.

All V2.0 work accumulates in `v2.0-release`. After all pillars are complete and verified, `v2.0-release` will be merged into `main` through one final release PR.

## Branch Structure

```text
main
└── v2.0-release
    ├── implement-today-view
    ├── pillar-2-progress-analytics
    ├── pillar-3-srs-retune-graduation
    ├── pillar-4-leetcode-sync-foundation
    ├── pillar-5-pending-imports
    └── pillar-6-done-today-feed
```

## PR Base Rules

- Pillar PRs target `v2.0-release`.
- The final V2.0 release PR targets `main`.
- No V2.0 product branch should target `main` directly.
- Keep `main` stable until V2.0 is complete.

## Pillars

- Pillar 1 - Today IA + Claude Design visual port
- Pillar 2 - Progress owns analytics
- Pillar 3 - SRS interval retune + 5-star graduation
- Pillar 4 - LeetCode Activity connection + sync foundation
- Pillar 5 - Pending LeetCode imports
- Pillar 6 - Done Today activity feed

## Cross-Pillar Product Gates

- No fake LeetCode copy in production
- No date strip/calendar on Today
- Today remains action-focused
- Progress owns analytics
- Confidence only changes from explicit user rating
- LeetCode solves do not auto-complete reviews
- Pending imports stay out of the review queue while pending
- Existing localStorage-first architecture remains intact
- Existing cloud sync durability remains intact
- Mobile follow-up impact documented

## Verification Commands

Run for each pillar PR when relevant:

```bash
npm run typecheck
npm run lint
npm test
npm run build
npm run test:e2e
```

## Final V2.0 Release Gate

Before merging `v2.0-release` into `main`:

- All six pillars merged into `v2.0-release`
- Full verification commands pass
- Vercel preview reviewed
- Manual signed-out localStorage smoke test
- Manual signed-in cloud sync smoke test
- Dev seed flow tested
- LeetCode connected-profile flow tested
- LeetCode private/unavailable-profile flow tested
- README/release notes updated
- Final release PR opened from `v2.0-release` to `main`

## Recommended GitHub Setup

If possible, protect `main` and `v2.0-release`.

Recommended for `main`:

- require pull requests
- require status checks
- disallow force pushes
- optionally require review before merge

Recommended for `v2.0-release`:

- require pull requests
- require status checks
- allow pillar PRs only
- disallow direct product-code merges without review

## Manual PR Retargeting

If a V2.0 PR accidentally targets `main`, change its base branch to `v2.0-release`.

GitHub UI:

Pull request -> Edit -> base branch -> `v2.0-release` -> Change base.

After changing base, verify the diff carefully.

## Warning

Do not merge V2.0 work into `main` until all six pillars are complete, verified, and ready for the final release PR.
